# CodePocket

Мобильная веб-IDE: код пишется с телефона, а выполняется на вашем сервере.
Экраны — Главная (серверы и проекты), Файлы (редактор), Консоль (терминал по
SSH), ИИ (Claude и Codex), Профиль.

Бэкенд — чистый Python без внешних зависимостей: только стандартная библиотека,
свой WebSocket поверх `http.server`. Фронтенд — один самодостаточный HTML-файл,
CodeMirror и xterm.js лежат локально, без CDN.

## Состав

| Файл | Что это |
|---|---|
| `server.py` | весь бэкенд: HTTP+WebSocket, SSH к серверам пользователей, чаты агентов |
| `agent.py` | агент через Anthropic API (запасной режим, когда своего сервера нет) |
| `static/index.html` | всё приложение целиком: разметка, стили, логика |
| `static/vendor/` | CodeMirror и xterm.js локально, без CDN |
| `tests/` | смоук-тесты защитных мест (пути, шифрование, роли, права на файлы) |
| `deploy.sh` | выкладка в прод с прогоном тестов |

## Разработка и выкладка

Репозиторий и прод — **разные каталоги**. Здесь идёт разработка, сервис работает
из `/opt/codepocket`; правки в рабочем каталоге systemd — прямой путь к тому,
чтобы уронить прод незакоммиченным изменением.

```bash
python3 -m unittest discover -s tests -v   # тесты
./deploy.sh --dry-run                      # посмотреть, что уедет
sudo ./deploy.sh                           # выложить и перезапустить
```

`deploy.sh` сам прогоняет тесты и проверку синтаксиса, копирует код в
`DEPLOY_DIR` (по умолчанию `/opt/codepocket`), перезапускает сервис и проверяет,
что он поднялся. Каталог задаётся переменной: `DEPLOY_DIR=/srv/cp ./deploy.sh`.

Нужен Python 3.6+ и systemd. Внешних пакетов нет, `pip install` не требуется.

## Настройки

Живут в `/etc/codepocket.env` (в репозиторий не входит), данные пользователей —
в `/var/lib/codepocket/`.

| Переменная | Значение |
|---|---|
| `IDE_HOST` / `IDE_PORT` | адрес и порт (по умолчанию `127.0.0.1:9500` — наружу только через прокси) |
| `IDE_DATA_DIR` | где лежат база, чаты, история, аудит-лог |
| `IDE_DEV_INVITE` | инвайт-код, дающий роль разработчика |
| `IDE_OPEN_SIGNUP` | `1` — регистрация без инвайта открыта **всем**, кто знает адрес |
| `ANTHROPIC_API_KEY` | общий ключ для запасного режима агента |
| `CP_MODEL` | модель агента (по умолчанию `claude-opus-5`) |
| `CP_MAX_TOKENS` | потолок ответа агента (16000) |
| `CP_DAILY_TOKENS_DEV` / `_USER` | суточные квоты токенов по ролям |
| `TG_BOT_TOKEN` | токен бота для входа через Telegram Mini App |
| `TG_ALLOWED_IDS` | кого пускать. **Пусто = пускаем любого пользователя Telegram** |
| `TG_ADMIN_IDS` | кому давать роль разработчика |
| `CP_ALLOW_LOCAL_TERMINAL` | `1` — разрешить терминал на самой машине приложения |
| `CP_TERMINAL_API_KEY` | `1` — пробрасывать общий ключ Anthropic в терминалы пользователей |

Две настройки открывают доступ к Linux-учёткам на машине и требуют осознанного
решения: `IDE_OPEN_SIGNUP=1` и пустой `TG_ALLOWED_IDS` при заданном
`TG_BOT_TOKEN`. Каждая по отдельности означает «кто угодно снаружи может завести
себе аккаунт с shell».

## Модель безопасности

Что защищает и от чего:

* **Изоляция пользователей** — Linux-правами. У каждого своя учётка, домашняя
  папка `0750`, sudo нет. Терминалы и агент работают под учёткой пользователя
  (`setgroups` + `setgid` + `setuid`), лимиты памяти и процессов — через
  cgroup (`systemd-run --scope`), с откатом на `rlimit`.
* **Пути** — `safe_path()` резолвит символьные ссылки и сверяет с домашней
  папкой по разделителю. Имена проектов и агентов, попадающие в пути,
  проверяются по белому списку.
* **Доступы к серверам** — шифруются по схеме encrypt-then-MAC (поток на
  SHA-256 + HMAC-SHA256 на отдельном ключе). Не сошёлся тег — читать
  отказываемся. Ключ в `secret.key`, права `0600`.
* **Файлы с секретами** — создаются сразу с `0600` через `write_private()`,
  а не сужаются после записи.
* **Сессии** — cookie `HttpOnly; SameSite=Lax; Secure`, срок 90 дней.
  Origin сверяется на всех POST и при подключении к терминалу.
* **Перебор** — лимит по IP и блокировка учётки на 5 минут после 5 ошибок PIN
  (PBKDF2-SHA256, 100 000 итераций). Реальный IP берётся из последнего элемента
  `X-Forwarded-For` и только если запрос пришёл от локального прокси.
* **Права администратора** — роль `dev`, проверяется отдельно в GET- и
  POST-ветках. Запись без роли считается обычным участником.

Это не контейнеры. Пользователи разделены правами ОС, и разделение настолько
надёжно, насколько надёжно ядро. Для публичного запуска нужна настоящая
изоляция.

## Чего в репозитории нет и не должно быть

Ключей, паролей, `users.json`, `secret.key`, `.env`. Всё это лежит на сервере
и закрыто через `.gitignore`.
